# Challenge Mission 기록

## 구현

- 이메일 중복: HTTP 409, MEMBER4091, 이미 사용 중인 이메일입니다.
- 닉네임 중복: HTTP 409, MEMBER4092, 이미 사용 중인 닉네임입니다.
- 회원 엔티티의 UNIQUE 제약에 uk_member_email, uk_member_nickname 이름을 지정했다.
- 전역 예외 처리에서 DataIntegrityViolationException의 가장 구체적인 원인에 포함된 제약 이름을 식별해 동일한 오류 형식으로 반환한다. SQL 오류 원문은 응답으로 노출하지 않는다.
- 식별되지 않은 DB 제약 위반은 공통 DB409 응답을 반환한다.

## 사전 중복 검사만으로 충분하지 않은 이유

요청 A와 B가 거의 동시에 들어오면 두 요청 모두 저장 전에 중복 조회를 실행해 아직 해당 값이 없다는 결과를 받을 수 있다. 이후 두 요청이 같은 값을 저장하려 하면 DB UNIQUE 제약이 두 번째 저장을 거절한다. 따라서 사전 검사는 사용자에게 빠르게 안내하는 역할을 하고, DB 제약은 동시성 상황의 최종 무결성을 보장한다. DB 예외도 전역 처리로 같은 JSON 구조와 구분된 code/message로 돌려줘야 한다.

## 검증 결과

동시 요청 16건을 자동 검증한 뒤 브라우저에서 각 8건을 다시 실행하고 캡처했다. 기존 필수 미션 API 검증 15건도 재실행해 모두 통과했다.

구현 소스는 저장소의 movie 디렉터리에 있다. 기존 MySQL DB에 적용할 때는 이름이 지정된 UNIQUE 제약으로 스키마를 마이그레이션해야 한다. 이름이 다른 기존 제약은 공통 DB409로 처리된다.
